# ورود آزمایشی با هویت مستقل برای هر شماره

این مسیر فقط برای تست شخصی و build توسعه است و جایگزین احراز هویت واقعی پیامکی نیست.

## تنظیمات لازم در Supabase

در بخش Edge Functions → Secrets این مقادیر را تعریف کن:

- `DEV_PHONE_LOGIN_ENABLED=true`
- `DEV_PHONE_LOGIN_CLIENT_KEY`: مقدار تصادفی حداقل ۳۲ کاراکتری
- `DEV_PHONE_LOGIN_CODE`: کد آزمایشی که در صفحه OTP وارد می‌کنی
- `DEV_PHONE_LOGIN_HMAC_SECRET`: مقدار تصادفی حداقل ۳۲ کاراکتری
- `DEV_PHONE_LOGIN_ALLOWED_PHONES`: شماره‌های تست مجاز با قالب `09xxxxxxxxx` و جداشده با کاما

هیچ‌کدام از این مقادیر را در Git، فایل asset یا سورس commit نکن. کلید کلاینت فقط در build توسعه محلی قرار می‌گیرد و از فایل کامپایل‌شده قابل استخراج است؛ بنابراین این قابلیت صرفاً برای تست شخصی است. allowlist سمت سرور محدودیت اصلی شماره‌هاست.

## اجرای اپ

```bash
flutter run --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=... --dart-define=ENABLE_DEV_PHONE_LOGIN=true --dart-define=DEV_PHONE_LOGIN_CLIENT_KEY=...
```

در نسخه Release ورود آزمایشی حتی با وجود define غیرفعال می‌ماند، چون کد علاوه بر define مقدار `kDebugMode` را هم بررسی می‌کند. این build را منتشر یا در اختیار دیگران قرار نده.

## رفتار هویت

شماره با قالب ایران نرمال می‌شود و سرور برای هر شماره یک ایمیل داخلی غیرقابل‌استفاده برای دریافت ایمیل و رمز مشتق‌شده از HMAC می‌سازد. رمز هرگز به اپ ارسال نمی‌شود. پس از ورود، Supabase Auth یک user_id مستقل صادر می‌کند و RLS موجود بر اساس `auth.uid()` داده‌های آن مشتری را جدا می‌کند.

هیچ wallet یا loyalty قدیمی به‌صورت خودکار منتقل نمی‌شود. انتقال داده‌های حساب مشترک باید پس از تطبیق مالکیت انجام شود.
